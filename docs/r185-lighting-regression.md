# Fixing black lighting with r185.1

2026-09-09. This investigation covers the source in this repository. It started
from the user-provided report at
`three-modeler/artifacts/gtvbao-upsampling/EXAMPLE-AUDIT.md`.
No code or dependencies in other projects were changed.

## Cause and fix

`createGtvbaoDepthAwareAo()` first evaluated `viewNormal` inside the
`_upsampleEnabled > 0.5` branch. In the actual WGSL generated by r185.1,
initialization of the normals shared with lighting was also placed inside
that branch.

```wgsl
if (upsampleEnabled > 0.5) {
    normalViewGeometry = normalize(v_normalViewGeometry);
    NORMAL_normalView = normalViewGeometry;
    normalView = NORMAL_normalView;
    // depth-aware upsample ...
} else {
    // ordinary AO sample ...
}
// Lighting later reads normalView, including when the branch was skipped.
```

At full AO resolution, the branch is skipped and subsequent lighting reads a
normal with its initial value of zero. Direct light and normal-dependent indirect
light are lost even when the AO texture contains valid values. Pass counts and
finite-value checks alone therefore did not detect the failure.

The fix in `src/GTVBAOUpsample.js` evaluates `viewNormal.toVar()` before the
branch and uses that value inside the upsample. The resulting WGSL initializes
the normals before the branch. AO formulas, public APIs, and dependency versions
are unchanged. No individual Three.js commit was reverted in isolation, so this
investigation does not attribute the failure to a specific upstream commit.

## Failures measured before the fix

`test/webgpu/lighting.html` reproduces the issue with one sphere, ambient light,
one directional light, and a constant 0.6 AO texture. A separate pass using
`builtinAOContext(float(0.6))` provides the reference. The reproduction requires
no AO computation, denoising, TRAA, or depth pre-pass execution.

| Condition | r184 | r185.1 before fix | r185.1 after fix |
| --- | --- | --- | --- |
| Ambient light only (diagnostic isolation) | — | Maximum error 0 | — |
| Ambient + directional light, minimal lighting fixture | Maximum error 0 | **Maximum error 0.64453125, FAIL** | Maximum error 0 |

Image comparisons were also added to the production example before applying the
fix. They failed for raw-lit, denoised-lit, after-debug-lit, and the full-resolution
zero-intensity cases. With the camera configuration used at that point, raw-lit
retained approximately 0.31856 of the reference luminance in the central region;
approximately 0.61273 of the compared pixels darkened by more than 95%.
The final fixture also fixes the camera position and FOV, so those measurements
are not treated as an A/B comparison against the final images under an identical
camera configuration.

## Regression tests

- **Minimal lighting fixture**: Compares linear images from the production helper
  and an independent constant-AO reference. Requires maximum error below `2e-5`,
  a nonblack reference sphere center, and finite output values. This also rejects
  a false pass from two black images. Add `?shaders=1` to display generated shaders.
- **39 production example cases**: Extends the existing 33 cases with zero intensity
  for raw/denoised AO at full/half resolution, plus regular raw/denoised lighting at
  half resolution. Non-TRAA lighting is compared on frames 1 and 5 after each mode
  switch.
- **Zero intensity**: Compares against the same session's AO-off lighting. Readback
  is Float32, but the lighting pass uses a HalfFloatType target, so each RGB component
  may differ by one half-float ULP, with mean luminance ratio error limited to `1e-5`.
  Even r184 failed a strict `2e-5` comparison because of rounding differences up to
  `0.00048828125`. On frame 5, every texel in raw AO and any denoised AO rendered for
  that scenario must also equal 1.
- **Regular lighting**: Requires at least 50% of the AO-off luminance in the central
  region, with no more than 10% of compared pixels darkened by over 95%. These are
  blackening guards, not AO quality scores.
- **14 existing upsample cases**: Retains GPU comparisons for full/half/quarter
  resolution, ordinary/logarithmic depth, normal encoding, disabled MIPs, and
  disabled upsampling.

## Final verification

Tests ran in the in-app browser on the same machine. The regular development
server used Three.js 0.184.0. A separate Vite server aliased the complete installed
0.185.1 package while serving the same repository sources. No external package
contents were modified.

| Version / backend | Minimal lighting fixture | Production example | Upsample |
| --- | --- | --- | --- |
| 0.184.0 / WebGPU | Error 0 | 39 / 39 | 14 / 14 |
| 0.185.1 / WebGPU | Error 0 | 39 / 39 | 14 / 14 |
| 0.184.0 / WebGL2 | Error 0 | 39 / 39 | 14 / 14 |
| 0.185.1 / WebGL2 | Error 0 | 39 / 39 | 14 / 14 |

Maximum upsample error was `1.78814e-7` on WebGPU and `1.19209e-7` on WebGL2.
The final runs of each page produced no rendering console errors or warnings.

`npm run typecheck`, `npm test` (8 files, 38 tests), and `npm run build` passed.
`npm run lint` was attempted but could not run because no lint script is defined.

For reproduction instructions, see [test/webgpu/README.md](../test/webgpu/README.md)
and [serve-version.mjs](../test/webgpu/serve-version.mjs).

## Verification limits

The new identity comparison does not cover TRAA lighting images; those cases
retain the existing pass-count and finite-value checks. In the production example,
"frame 1" means the first frame after switching modes, not starting every mode
with a new renderer. The minimal lighting fixture compares the initial render.
Verification does not include pixel-for-pixel equality between r184 and r185 for
all outputs, other GPUs, reapplication to external projects, or npm publication.
